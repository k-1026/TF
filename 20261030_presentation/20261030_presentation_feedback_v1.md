## 1. 요약

1. **인터뷰는 SNS 리뷰로 대부분 대체할 수 있다.** 매장 인터뷰 양식 11개 필드 중 7개는 리뷰·매장 SNS·공공데이터로 채울 수 있다. 사장님만 아는 이야기(메뉴 사연, 금지 사항, 동의)만 짧은 확인으로 남긴다.
2. **참여율·완주율·재방문 의향은 정의부터 고정해야 한다.** 특히 '참여율'은 매장 참여율과 방문객 참여율로 나눠야 하고, '재방문 의향'(설문)과 '실제 재방문'(스탬프 기록)을 따로 잰다.
3. **에이전트에게는 지표 숫자만이 아니라 '정의·표본 수·측정 방법'을 함께 넣는다.** 그래야 에이전트가 근거가 약한 숫자로 판단하지 않는다.
4. **인풋 튜닝은 "조건 → 바꿀 입력 → 확인할 지표" 규칙표로 정한다.** 한 번에 하나만 바꾸고, 바꾼 내용을 기록하며, 최종 반영은 팀이 승인한다.
5. 바로 할 수 있는 일은 **리뷰 수집 양식 확정**과 **지표 정의서 확정**이다. 목표 기준값은 파일럿 1회차 결과로 정한다.

## 3. 해결 방안 ① 인터뷰를 SNS 리뷰로 대체하기

### 3-1. 쓸 수 있는 공개 데이터

| 데이터 | 얻을 수 있는 것 | 수집 방법 [제안] | 주의 |

### 3-2. 인터뷰 양식 필드별 대체 가능 여부

`brand/20261028_cafe_character_system_v1.md` 7-1 매장 인터뷰 양식 기준이다.

| 필드 | 대체 자료 | 대체 가능 | 남는 확인 |
|---|---|---|---|
| `store_name`, `location` | 지도 앱, 인허가 데이터 | ● 완전 | — |
| `signature_menu` | 리뷰 메뉴 언급 빈도 1위 + 매장 SNS 대표 메뉴 | ● 완전 | 리뷰 1위와 사장님 추천이 다르면 확인 |
| `menu_story` | 매장 SNS 소개글, 기사 | ◐ 일부 | 기사가 없으면 사장님 확인 필요 |
| `opening_date` | 인허가 데이터, 매장 SNS 첫 게시물 | ● 완전 | 이전 개업·확장 이전 여부 |
| `vibe_keywords` | 리뷰 형용사 상위 3개 (단골 관점 대체) | ● 완전 | 사장님 관점 1회는 선택 |
| `daegu_link` | 기사, 매장 소개글, 지역 자료(keyword_map 자산) | ◐ 일부 | 사장님 개인의 대구 이야기는 확인 필요 |
| `craft` | 리뷰("직접 로스팅", "매일 팥을 끓인다"), 매장 SNS | ◐ 일부 | 사실 여부 확인 |
| `colors`, `photos` | 공개 사진에서 색만 추출해 기록 | ◐ 일부 | **실제 사용 사진은 매장 제공본만** (저작권) |
| `dialect_level` | 사장님 답글 말투 | ◐ 일부 | 매장 선택 |
| `no_go` | 대체 불가 | ○ 없음 | 사장님 확인 필수 |
| `consent` | 대체 불가 | ○ 없음 | 서면 동의 필수 |

→ **11개 중 완전 대체 4개, 일부 대체 5개, 대체 불가 2개.** 대체 불가 2개(`no_go`, `consent`)는 원래 계획에 있던 **'매장 확인 1회'** 단계(`inventory/20261028_partner_store_campaign_v1.md` 2장 ⑥)에서 함께 받는다. 별도 인터뷰 일정이 필요 없다.

### 3-3. 방문객 인터뷰(10~15명) 대체

| 원래 목적 (09장 PHASE 1) | 리뷰로 대체하는 방법 [제안] | 한계 |
|---|---|---|
| 코스 수요 확인 | 블로그 후기에서 '같은 날 함께 들른 가게' 조합을 세어 실제 동선 파악 | 후기를 쓰는 사람만 반영됨 |
| 리워드 수요 확인 | 리뷰에서 굿즈·스탬프·쿠폰 언급 여부, 다른 지역 스탬프 투어 후기 분석 | 우리 리워드에 대한 직접 반응은 아님 |
| 불편 요소 확인 | 리뷰 부정 키워드(대기, 주차, 좌석, 가격) 집계 | 매장별 편차가 큼 |

→ 리뷰는 **"이미 일어난 행동"**을 잘 보여 주고, **"새 기획에 대한 반응"**은 보여 주지 못한다. 캐릭터 시안·리워드 반응은 파일럿 현장에서 짧은 설문(QR 3문항)으로 받는다.

### 3-4. 리뷰 데이터의 한계와 대응

| 한계 | 대응 [제안] |
|---|---|
| 긍정 편향, 체험단·광고 리뷰 | '체험단', '협찬', '제공받아' 표시가 있는 리뷰는 집계에서 뺀다 |
| 리뷰 수가 적은 신생 매장 | 리뷰 기준 수량(예: 30개 [가설]) 미만이면 **인터뷰 보강 대상**으로 표시 |
| 오래된 리뷰 | 최근 12개월 리뷰만 사용 [가설] |
| 개인정보·저작권 | 작성자 아이디·사진·원문은 저장하지 않는다. **키워드·빈도·요약만** 저장하고 출처 URL과 수집일을 남긴다 |
| 사실 오류 (리뷰가 틀린 정보를 말함) | 에이전트 입력에서 리뷰 기반 정보는 `source: review`로 표시하고, 캐릭터 시트 확정 전에 매장 확인 |

### 3-5. 결론: '리뷰 기본 + 인터뷰 선택' 하이브리드

```
공개 데이터 수집(리뷰·SNS·기사·공공데이터)
  → 매장 프로필 초안 자동 작성 (필드마다 출처 표시)
  → 리뷰 부족·핵심 매장만 10분 인터뷰 (선택, 5문항)
  → 매장 확인 1회 (no_go, consent, 사실 수정)
  → 캐릭터 생성
```

- 인터뷰를 할 경우 **5문항**으로 줄인다: ① 메뉴가 생긴 사연 ② 가게와 대구의 연결 ③ 이 가게만의 고집 ④ 캐릭터에 넣지 말아야 할 것 ⑤ 손님에게 듣고 싶은 말

## 4. 해결 방안 ② 지표의 기준을 정확하게 정하기

### 4-1. 지표 정의서 [제안]

| 지표 | 정의 (분자 / 분모) | 기간·단위 | 측정 방법 | 주의 |
|---|---|---|---|---|
| **매장 참여율** | 참여 확정 매장 수 / 참여 제안한 매장 수 | 모집 기간, % | 모집 기록표 | 제안 방식(방문·전화·DM)을 함께 기록 |
| **방문객 참여율** | 스탬프 1개 이상 받은 사람 수 / 배포한 지도(여권) 수 | 코스 운영 기간, % | 지도 일련번호 + 스탬프·QR 기록 | 지도를 받지 않고 QR만 쓴 사람은 따로 센다 |
| **완주율** | 코스 매장 스탬프를 모두 받은 사람 수 / 스탬프 1개 이상 받은 사람 수 | 코스 운영 기간, % | 스탬프 회수 또는 QR 기록 | 분모를 '배포 수'로 잡으면 참여율과 섞이므로 금지 |
| **단계별 이탈률** | k번째 매장까지 받은 사람 중 k+1번째를 받지 않은 비율 | 매장 순서별, % | QR 기록의 순서 | **어느 매장에서 멈추는지**를 보는 핵심 보조 지표 |
| **재방문 의향** | 설문 "다른 코스에도 오겠다" 5점 척도에서 4·5점 비율 (Top-2) / 응답자 수 | 완주·이탈 직후, % | QR 설문 3문항 | 응답자 수를 반드시 같이 적는다 |
| **실제 재방문** | 다른 코스(또는 다음 시즌)에서 다시 스탬프를 받은 사람 수 / 첫 코스 참여자 수 | 첫 참여 후 90일 [가설], % | 같은 여권 번호·QR 계정 | 의향과 행동을 섞지 않는다 |
| 쿠폰 사용률 | 사용한 쿠폰 수 / 지급한 쿠폰 수 | 유효 기간, % | 매장 회수 | 매장별 집계 방식 통일 |
| 스탬프 인증 수 | 기간 중 인증 건수 | 일·주, 건 | QR 기록 | 같은 사람의 중복 인증은 하루 1회로 제한 |

- **모든 지표에 같이 적을 것**: 기간, 코스, 표본 수(분모), 측정 방법, 집계자. 발표자료 04장의 "조사 연도·정의·집계 범위를 분명히" 원칙을 성과 지표에도 똑같이 적용한다.
- **종이 스탬프만 쓰면** 이탈 지점과 실제 재방문은 잴 수 없다. 최소한 **QR 인증(웹 기록)**을 같이 써야 위 지표가 모두 나온다. 발표자료 07장의 "종이 지도부터 시작"과 충돌하지 않도록 **종이 지도 + QR 인증 병행**을 제안한다.

### 4-2. 기준값(목표치)을 정하는 방법

| 단계 | 방법 |
|---|---|
| 파일럿 전 | 목표 숫자를 단정하지 않는다. 팀 가설값만 적고 **[가설]**로 표시 |
| 파일럿 1회차 | 실제 값을 **기준선(baseline)**으로 삼는다 |
| 2회차부터 | 기준선 대비 변화로 평가 ("완주율 ○%p 상승") |
| 외부 비교 | 다른 지역 스탬프 투어의 완주율 자료가 있으면 참고하되, 정의가 같은지 먼저 확인 [확인 필요] |

### 4-3. 표본이 작을 때의 원칙

- 분모가 작으면 비율이 크게 흔들린다. **분모 30 미만 [가설]**이면 비율 대신 "10명 중 4명"처럼 숫자로 적고, 튜닝 판단에 쓰지 않는다.
- 파일럿 규모(1~2개 코스, 4~6주)에서는 매장별 비교보다 **코스 전체 지표와 이탈 지점**을 먼저 본다.

| ① 지역 자산 | `research/keyword_map.md` 재분류 v2의 **자산** 키워드 (정보 판정 키워드는 참고만) | 분기 |
| ② 매장 프로필 | 3장 방식으로 만든 매장별 필드 + 필드마다 출처(`review` / `sns` / `article` / `public_data` / `interview` / `store_confirmed`) | 매장 추가·변경 시 |
| ③ 캐릭터 시트 | 하루콩 변형 슬롯 | 매장 확인 후 |
| ④ **성과 지표** | 4장 지표 + 정의·표본 수·측정 방법 | 주 1회 (파일럿 중) |
| ⑤ 반응 데이터 | 캐릭터별 SNS 반응, 리뷰 신규 키워드 | 주 1회 |
| ⑥ 변경 기록 | 지난번에 무엇을 바꿨고 결과가 어땠는지 | 변경할 때마다 |

### 5-2. 성과 지표 입력 형식 (예시)

```yaml
course: 교동
period: 2026-11-10 ~ 2026-12-07   # 예시 기간
version: pilot-1
metrics:
  visitor_participation:   # 방문객 참여율
    value: null            # 파일럿 후 입력
    numerator: null        # 스탬프 1개 이상
    denominator: null      # 지도 배포 수
    method: "지도 일련번호 + QR"
  completion_rate:         # 완주율
    value: null
    numerator: null
    denominator: null      # 스탬프 1개 이상 받은 사람
    method: "QR 기록"
  dropoff_by_store:        # 단계별 이탈률 (매장 순서대로)
    - {order: 1, store: "매장A", dropoff: null}
    - {order: 2, store: "매장B", dropoff: null}
  revisit_intent:          # 재방문 의향 Top-2
    value: null
    respondents: null
    method: "QR 설문 5점 척도"
  actual_revisit_90d: null
reliability: low           # 분모 30 미만이면 low → 튜닝 판단에 쓰지 않음
notes: "우천 2일, 매장B 임시휴무 1일"
```

- `reliability` 값이 `low`이면 에이전트는 **제안만 하고 변경하지 않는다.**
- `notes`에 날씨·휴무·행사처럼 지표에 영향을 준 외부 요인을 적는다. 그래야 에이전트가 원인을 잘못 짚지 않는다.

## 6. 해결 방안 ④ 인풋 튜닝 기준

### 6-1. 튜닝 규칙표 [제안·가설]

| 조건 (지표 신호) | 의심 원인 | 바꿀 입력 | 바꾸는 내용 | 다음에 확인할 지표 |
|---|---|---|---|---|
| 특정 매장 다음에서 이탈률이 코스 평균보다 크게 높음 | 거리, 영업시간, 그 매장 경험 | 코스 설계 (매장 순서·구성) | 순서 변경 또는 해당 구간 안내 강화. 매장 문제면 매장과 협의 | 해당 구간 이탈률 |
| 완주율 낮음 + 코스 매장 수 많음 | 코스가 하루에 비해 길다 | 코스 설계 | 매장 수 축소 (예: 5 → 3) | 완주율 |
| 참여율 낮음 (지도는 나갔는데 스탬프 시작이 적음) | 첫 매장 진입 장벽, 홍보 문구 | SNS·지도 문구, 첫 매장 캐릭터 노출 | 첫 매장 하루콩을 홍보 주인공으로 | 방문객 참여율 |
| 재방문 의향은 높은데 실제 재방문이 낮음 | 다음 코스로 넘어갈 이유 부족 | 리워드 설계 | 다른 코스 연결 리워드(레어 등급) 강화 | 실제 재방문 |
| 특정 캐릭터의 SNS 반응이 계속 낮음 | 캐릭터 매력, 스토리 축 | 캐릭터 시트·스토리 축 | 성격·말투 조정, 다른 스토리 축(이웃 관계 등)으로 노출 | 캐릭터별 반응 |
| 리뷰 키워드와 캐릭터 설정이 어긋남 | 프로필 입력 오류 | 매장 프로필 | 리뷰 최신 키워드로 성격 슬롯 재검토 → 매장 확인 | 매장 만족도 |
| 쿠폰 사용률이 매장별로 크게 다름 | 매장 안내 차이 | 매장 키트·직원 안내문 | 안내문 보완 | 쿠폰 사용률 |

### 6-2. 튜닝할 때 지키는 원칙

1. **한 번에 하나만 바꾼다.** 두 개를 동시에 바꾸면 무엇이 효과였는지 알 수 없다.
2. **표본 기준을 넘을 때만 바꾼다.** 분모 30 미만 [가설]이면 관찰만 한다.
3. **비교 기간을 맞춘다.** 바꾸기 전과 후를 같은 길이(예: 2주)로 비교하고, 날씨·행사 같은 외부 요인을 기록한다.
4. **바꾼 내용을 기록한다.** 입력 ⑥ 변경 기록에 날짜·조건·변경 내용·결과를 남긴다. 이것이 다음 튜닝의 근거가 된다.
5. **에이전트는 제안하고, 팀이 승인한다.** 캐릭터 설정·매장 관련 변경은 매장 확인까지 거친다.
6. **바꾸지 않는 것을 정해 둔다.** 기본형 규칙, 가드레일(실존 인물·종교·의료 표현 금지), 매장 동의 범위는 지표가 나빠도 튜닝 대상이 아니다.

### 6-3. 튜닝 주기

| 시점 | 할 일 |
|---|---|
| 매주 (파일럿 중) | 지표 입력, 이탈 지점 확인. 큰 변경 없이 관찰 |
| 2주차 | 첫 튜닝 1건 (규칙표에서 가장 신호가 강한 것 하나) |
| 파일럿 종료 | 기준선 확정, 다음 코스용 입력 기본값 갱신 |
| 시즌 종료 | 규칙표 자체를 다시 검토 (맞지 않는 규칙 삭제·수정) |

## 9. 한계 및 추가 확인

- 플랫폼별 리뷰 수집 허용 범위와 공식 API 제공 범위는 **아직 확인하지 않았다.**
- 표본 기준(30), 리뷰 기간(12개월), 재방문 측정 기간(90일)은 모두 **팀 가설**이며, 파일럿 후 조정한다.
- 다른 지역 스탬프 투어의 완주율·재방문율 자료는 찾지 않았다. 외부 기준값이 필요하면 따로 조사한다.
- 리뷰 기반 프로필은 "손님이 본 가게"다. 사장님이 보는 가게와 다를 수 있으므로 매장 확인 단계를 없애지 않는다.
